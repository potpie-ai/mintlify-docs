When a reported issue is received, it traverses the <a href="/concepts/knowledge-graph" className="mode-link">knowledge graph</a> across every affected component to determine where the problem truly originated.

It isolates the root cause to a specific file and line of code, then returns a precise and targeted fix grounded in the actual implementation.

To start using Debug, see the <a href="/tutorials/trace-and-fix" className="mode-link">Trace and Fix Bugs tutorial</a>.

## How It Investigates

Debug separates the reported problem from any fix the user may have suggested. User-reported symptoms and suggested fixes are treated as starting points for investigation, not conclusions. The goal is to find the real issue, which is often upstream of where the problem surfaces.

Once the origin is found, Debug evaluates where the fix should live. A fix at the source prevents the problem for every downstream caller automatically. A fix at the symptom only handles one path. Debug always identifies which type of fix it's applying and why.

For simple issues it runs end to end. For problems spanning multiple services it delegates to specialized subagents.

---

## What It Returns

A root cause traced to its origin, a clear path from origin to symptom, and a fix that addresses the generalized issue — not just the specific instance that was reported.
## Eight-step methodology

Potpie applies an **eight step methodology** to every issue:

<Steps>
  <Step title="Understand and validate">
    Confirms the reported behavior against the codebase, identifies every component involved, and establishes what the correct behavior should be at the point of failure.
  </Step>
  <Step title="Explore and hypothesize">
    Traverses the relevant code paths in the <a href="/concepts/knowledge-graph" className="mode-link">knowledge graph</a> and generates candidate explanations for the failure.
  </Step>
  <Step title="Identify the root cause">
    Pins the failure to a specific file and line, identifying the exact instruction that introduces the faulty state.
  </Step>
  <Step title="Generalize the issue">
    Checks whether the same defect pattern appears elsewhere in the codebase.
  </Step>
  <Step title="Design a solution">
    Generates a targeted fix scoped to the **root cause**.
  </Step>
  <Step title="Scrutinize and refine">
    Evaluates the fix against edge cases and traces potential side effects through the <a href="/concepts/knowledge-graph" className="mode-link">dependency graph</a>.
  </Step>
  <Step title="Implement">
    Produces the corrected code with exact file paths and line references.
  </Step>
  <Step title="Final verification">
    Validates the fix against the original failure and checks for regressions.
  </Step>
</Steps>

## Investigation mode

Potpie resolves straightforward issues end to end. For failures that span multiple services or require deep dependency traversal, Potpie delegates to specialized subagents.

## Using the API

The <a href="/api-reference/endpoint/create-conversation-and-message" className="mode-link">Create Conversation and Message</a> endpoint opens a debug session against a <a href="/concepts/parsing" className="mode-link">parsed</a> project and returns the first investigation response in a single call.
