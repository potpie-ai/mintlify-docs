## Connecting a GitHub Account

1. Go to <a href="https://app.potpie.ai/sign-in" className="mode-link">Potpie </a>  → **Settings** → **Integrations**
2. Click **Connect GitHub**
3. Once completed with OAuth flow , Potpie stores your access token encrypted in PostgreSQL and links it to your account

<Note>A GitHub account already connected to a different Potpie user cannot be merged or transferred.</Note>



## Repository Access

Potpie resolves authentication for every repository request through the following priority order:

| Priority | Source |
|---|---|
| 1 | GitHub App installation token |
| 2 | `CODE_PROVIDER_TOKEN_POOL` |
| 3 | `CODE_PROVIDER_TOKEN` |
| 4 | `GH_TOKEN_LIST` |
| 5 | `CODE_PROVIDER_USERNAME` / `CODE_PROVIDER_PASSWORD` |

For local repositories, the filesystem path is used directly without token resolution. 


## Listing Repositories

`GET /github/user-repos` returns all repositories accessible to the authenticated user. Both the repositories available to parse and repositories already parsed as projects in Potpie.
```bash
curl http://localhost:8001/api/v2/github/user-repos \
  -H "x-api-key: YOUR_API_KEY"
```



## Pull Request Creation

When the <a href="/agents/code-generation-agent" className="mode-link">Code Generation Agent</a> creates a PR, it stages all changes, commits under `Potpie <hi@potpie.ai>`, pushes to the remote, and opens the PR on GitHub or GitBucket. The PR URL is streamed back to the user on completion.


## Token Storage

| Token | Where stored |
|---|---|
| User OAuth token | PostgreSQL with Fernet encryption |
| GitHub App private key | `GITHUB_PRIVATE_KEY` env var | 
| Installation token | In-memory, generated per request | 
| `GH_TOKEN_LIST` | Env var | 
| `CODE_PROVIDER_TOKEN` | Env var |
