## Repo Onboarding

When a repository is added, Potpie first determines whether it has already been parsed.  
- If a parsed graph exists for the same commit, parsing is skipped and the existing graph is reused.
- If no prior graph is found, the acquired repository is passed to the **File Analysis**.

## File Analysis

Every file in the repository is evaluated before parsing begins.  
- Files that cannot contain meaningful source code, such as images, binaries, or notebooks, are excluded early to avoid unnecessary processing.  
- Files with recognized source extensions are accepted as valid inputs and forwarded for structured analysis.

Each accepted file is then matched to a language grammar that determines how its symbols will be extracted.

## AST Querying

Each file is parsed into an abstract syntax tree and queried for symbols.  
- Every `function`, `class`, `method`, or `interface` discovered is recorded with its exact name and precise location in the codebase.  
- Each symbol is also classified to indicate whether it represents an original **definition or** a **reference** to a definition elsewhere.

## Graph Construction

- **Definitions** are represented as nodes in the knowledge graph.  
- **References** between symbols are represented as edges.  

This creates a navigable structural map of the codebase that captures not only what exists, but how components depend on one another.

## Storage

- Once all nodes and relationships are persisted, the repository is marked as `ready`.  
- Any subsequent request for the same commit skips parsing entirely and queries the existing graph directly.
