## Node Preparation

Once parsing is complete, Potpie takes every node in the graph and prepares it for understanding. 

Each node carries the raw source code of the symbol it represents. Before any processing begins, that source text is fully resolved , ensuring every node contains complete, self-contained code rather than references to other nodes.

## Cache Resolution

Before sending any code to an LLM, Potpie checks whether it has seen that exact source before. 
- Nodes whose code hasn't changed since a previous run are retrieved directly from cache, skip inference entirely. 
- Only nodes with new or changed code proceed to **LLM processing**.

---

## LLM Processing

Each uncached node is sent to an LLM, which produces a short description of what the code does and a set of `tag` classifying its role.

 Whether it handles authentication, database access, UI rendering, state management, and so on... Large nodes are split into chunks, processed separately, and then merged back into a single result before moving forward.

---

## Storage and Indexing

Once every node has a description and tags,Potpie generates a semantic embedding from each description and writes everything back to the knowledge graph. 
 
 The result is a fully annotated graph where every node is searchable by name, by role, and by meaning `ready` for agents to navigate and query.
