## Node Preparation

Post Parsing, Potpie ensures every node in the graph is prepared for understanding.

Each node carries the raw source code of represented symbol. Prior to any processing, concerned source text is fully resolved, ensuring every node contains complete, self-contained code rather than references to other nodes.

## Cache Resolution

Prior to sending any code to LLM, Potpie verifies if exact source is referred earlier.
- Nodes with no change in code since previous run, are retrieved directly from cache, & inference is skipped.
- Only nodes with new or changed code proceed to **LLM processing**.


## LLM Processing

Every uncached node is sent to LLM, which then does a short description of what the code does & a set of `tag` classifying its role, across the multiple actions like authentication, database access, UI rendering, state management, and so on... 

Large nodes are split into chunks, processed separately, and then merged back into a single result before moving ahead.



## Storage and Indexing

Once every node has a description and `tag` , Potpie generates a semantic embedding from each description and writes everything back to the knowledge graph. 
 
The result is a fully annotated graph wherein every node is searchable by name, by role, and by meaning `ready` for agents to navigate and query.
