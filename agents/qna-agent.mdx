---
title: QnA Agent
---

An agent that answers natural language questions about your codebase using semantic search and knowledge graph traversal.

**It accepts**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `user_question` | `string` | required | Natural language question about your codebase |
| `conversation_history` | `Message[]` | optional | Prior messages for follow-up context |
| `project_id` | `string` | required | Project identifier |
| `node_ids` | `string[]` | optional | Specific files or functions to scope the search |

**It returns**

| Field | Type | Description |
|-------|------|-------------|
| `response` | `string` | Markdown-formatted answer with precise file citations |
| `citations` | `string[]` | Exact file paths with line numbers referencing relevant code |

## Choose what you want to do

**Find code**
- If you ask where a feature or function lives, QnA Agent searches semantically across your files, maps relationships between components, and traces end-to-end flows to locate it.
- It surfaces the payment processor, API endpoints, database queries, or any other construct across multiple files & not just a grep match.
- The result is a structured answer showing exactly which files implement what you're looking for, with line level citations.

**Understand how something works**
- If you ask how a feature behaves, QnA Agent traces the full execution path : login endpoint → AuthService → Database → token generation → middleware — across every file involved.
- It synthesizes findings from multiple files into a coherent explanation with code examples inline, so you see the system as a whole.
- The answer follows the flow from start to finish so you understand what's happening, not just where the code lives.

**Explore architecture**
- If you ask about design patterns, dependency graphs, or system structure, QnA Agent maps what depends on what and surfaces the patterns your codebase uses.
- It identifies direct and transitive dependencies, lists callers and callees, and names the patterns like repository, factory, observer along with code examples for each.
- The result is a system-level overview backed by exact code references, not a generic architectural guess.
