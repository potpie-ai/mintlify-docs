The Codebase Q&A Agent answers questions about your codebase by navigating the <a href= "/concepts/knowledge-graph" className= "mode-link">knowledge graph</a> to find relevant code, trace dependencies, and return cited answers.

Prior to the agent runs, it prepares two pieces of context automatically:

- If `node_ids` are referenced in the query, it fetches their source code via `get_code_from_multiple_node_ids` and appends it as code context
- It always fetches the full file structure of the project via `fetch_repo_structure`

Both are injected into context before the agent processes your message.

## How It Works

### Understand the Question

The agent classifies every incoming question into one of four types:

- **What** (functionality, purpose),
- **How** (implementation, flow), 
- **Where** (location, usage sites), 
- **Why** (rationale, design decisions). 

It extracts key entities such as class names, function names, modules to determine scope.

<Note> For complex or multi-part questions, it calls `add_requirements` to track what needs answering and `add_todo` to break exploration into individual tasks prior to any navigation. </Note>

### Navigate the Codebase

The agent moves from broad to narrow:

- `ask_knowledge_graph_queries` : finds where relevant functionality lives in the graph
- `get_code_file_structure` : understands directory layout and module organization
- `get_code_from_probable_node_name` : retrieves specific named classes or functions
- `get_code_from_multiple_node_ids` : batch-fetches all relevant nodes collected so far
- `get_node_neighbours_from_node_id` : finds what calls this code and what this code calls
- `fetch_file` / `fetch_files_batch` : retrieves full files or specific line ranges
- `web_search_tool` / `webpage_extractor` : retrieves external documentation when the question involves a third-party library

<Note> `update_todo_status` is called after each exploration task completion. </Note>

### Respond

Answers are structured using clear section headings such as Main Answer, Details, Code Examples, and Related Components.

Every claim is grounded in the codebase and supported with a **precise file path and line number**, and all code snippets are presented in fenced blocks with appropriate language tags for clarity.

Prior to returning, the agent calls `get_requirements` and `read_todos` to verify that all aspects of the question are answered and all exploration tasks are complete.

## Calling the Agent
```bash
curl -X POST https://localhost:8001/api/v2/conversations/ \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_ids": ["proj_abc123"],
    "agent_ids": ["codebase_qna_agent"]
  }'
```

Once you have a `conversation_id`, send your question:
```bash
curl -X POST https://localhost:8001/api/v2/conversations/conv_xyz789/message/ \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "How is authentication implemented?",
    "node_ids": ["node_abc123"]
  }'
```
