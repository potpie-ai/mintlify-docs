## Authentication

Every request to the Potpie API requires an `x-api-key` header. To generate a key, see <a href="/tutorials/generate-api-key" className="mode-link">Generate an API Key</a>.

## Parse a Repository

Parsing builds the <a href="/concepts/knowledge-graph" className="mode-link">knowledge graph</a> for your repository. Send a `POST /api/v2/parse` request to begin.
```bash
curl -X POST http://localhost:8001/api/v2/parse \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "repo_name": "owner/repo",
    "branch_name": "main"
  }'
```

| Field | Required | Description |
|---|---|---|
| `repo_name` | Yes (cloud) | GitHub repository in `owner/repo` format |
| `repo_path` | Yes (local dev only) | Absolute path to a local repository. Only works when `isDevelopmentMode=enabled` |
| `branch_name` | No | Branch to parse. If omitted, passed as `null` |
| `commit_id` | No | Specific commit to parse |

Returns a `project_id` and `status`. Use the `project_id` in every subsequent request.

```json
{ "project_id": "<your_project_id>", "status": "submitted" }
```

## Check Parsing Status

Parsing runs asynchronously. Poll `GET /api/v2/parsing-status/{project_id}` until `status` is `ready`.
```bash
curl http://localhost:8001/api/v2/parsing-status/<your_project_id> \
  -H "x-api-key: YOUR_API_KEY"
```
```json
{ "status": "ready", "latest": true }
```

Status moves through `submitted` → `cloned` → `parsed` → `inferring` before reaching `ready`. If anything fails at any point, status becomes `error`.

<Warning>Do not create a conversation until `status` is `ready`.</Warning>

## Create a Conversation
```bash
curl -X POST http://localhost:8001/api/v2/conversations/ \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_ids": ["<your_project_id>"],
    "agent_ids": ["codebase_qna_agent"]
  }'
```

| Agent ID | Purpose |
|---|---|
| `codebase_qna_agent` | Answer questions about the codebase |
| `code_generation_agent` | Generate and modify code |
| `spec_generation_agent` | Generate technical specifications |
| `debugging_agent` | Trace and fix bugs |



Returns a `conversation_id`.

## Send a Message
```bash
curl -X POST http://localhost:8001/api/v2/conversations/<your_conversation_id>/message/?stream=true \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "How is authentication implemented?"
  }'
```

**Streaming response** (`stream=true`, default)

Each chunk is yielded as a JSON object as it arrives:
```json
{"message": "Authentication is handled in...", "citations": ["app/auth/service.py"], "tool_calls": []}
```

**Non-streaming response** (`stream=false`)
```json
{
  "message": "Authentication is implemented in...",
  "citations": ["app/auth/service.py", "app/middleware/auth.py"],
  "tool_calls": []
}
```
